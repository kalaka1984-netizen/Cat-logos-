## 2024-12-31 - [N+1 Style Listing and O(N) Wildcard Lookup Bottlenecks]
**Learning:** In SQLite-based GUI lists, calling Python queries per-row for aggregates (like counts/sums of fractions) creates classic N+1 bottlenecks. By replacing individual loops with an aggregated JOIN query (using SQLite's `TOTAL()` to safely handle 0.0 defaults for unmatched rows), list fetches achieved a massive 18x speedup. Furthermore, fetching database items using wildcard `LIKE` and filtering on Python-side is O(N) and has significant CPU overhead compared to direct SELECTs on indexed columns.
**Action:** Always favor SQLite `LEFT JOIN` and `GROUP BY` with safe aggregations like `TOTAL()` to fetch child counts/sums in bulk rather than individual SQL queries inside loops. Use direct exact matches on indexed columns rather than broad wildcard `LIKE` queries for single-row key lookups.
