## 2024-08-12 - N+1 Query Bottleneck in Style Listings
**Learning:** In list rendering views (like the style list in Engineering of Costs / Ingenieria de Costos), querying associated child records (such as style fractions) inside a loop creates an N+1 query problem, severely impacting list loading times. This can be completely resolved with a single SQL query utilizing `LEFT JOIN` and aggregating the child counts and sums via `COUNT()` and `TOTAL()`. Bypassing SQLite `LIKE` queries when the search filter is empty also prevents unnecessary table scanning.
**Action:** Always check list rendering loops for N+1 database operations and combine them into unified JOIN queries with SQLite aggregates (`TOTAL()`, `COUNT()`) where possible. Always check for empty search string filters to skip expensive search queries entirely.
